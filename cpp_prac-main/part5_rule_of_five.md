# Часть 5. Правило трёх/пяти

**Ветка GitHub:** `part5-rule-of-five` → merge в `main`

Все задания **дополняют** класс динамического массива из части 4.

## Теория

Правило трёх/пяти: если класс сам управляет ресурсом (в нашем случае — куча), то нужно явно определить: деструктор, конструктор копирования и оператор присваивания (правило трёх), а в C++11 и move-конструктор с move-оператором присваивания (правило пяти).

См.: <https://en.cppreference.com/w/cpp/language/rule_of_three>

## Задание 1

Реализовать **оператор присваивания** (`operator=`):

- защита от **самоприсваивания** (`if (this == &other) return *this;`);
- корректное копирование данных (без утечки памяти и «двойного освобождения»);
- вернуть `*this` для цепочечных присваиваний.

## Задание 2

Реализовать **move-конструктор**:

- «перехватить» указатель и размер из перемещаемого объекта;
- обнулить источник (указатель = `nullptr`, размер = 0).

## Задание 3

Реализовать **move-оператор присваивания**:

- освободить собственные данные;
- перехватить ресурсы из источника;
- корректно обработать самоприсваивание.

## Задание 4

Демонстрация на практике:

1. В `main`-программе показать **до и после** move: передачу массива в функцию/контейнер по значению — до move (дорогое копирование) и после (перенос указателя).
2. Убедиться с помощью AddressSanitizer (`-fsanitize=address`), что утечек и двойных освобождений нет:

```bash
g++ -std=c++17 -Wall -Wextra -fsanitize=address -g src/*.cpp -o main_asan
./main_asan
```
